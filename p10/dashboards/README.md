# Wazuh + Splunk Integration Dashboard Documentation

**Project:** P10 — Wazuh + Splunk SIEM Integration  
**File:** `p10/dashboards/wazuh_splunk_dashboard.xml`  
**Theme:** Dark (`theme="dark"`)  
**Target Environment:** Splunk Enterprise 10.4.3 (`http://127.0.0.1:18000`)  

---

## 1. Dashboard Overview

The **Wazuh + Splunk SIEM Integration Dashboard** unifies host-level EDR/XDR alert telemetry generated by the Wazuh Manager with cross-domain correlation within Splunk Enterprise. It maps Wazuh alert severity levels (0–15) to SOC severity tiers, provides real-time visibility into active agent health, highlights authentication attacks, maps adversary techniques to the MITRE ATT&CK framework, and offers a cross-index investigation timeline.

---

## 2. Panel Architecture & Section Mapping

The dashboard is structured into 6 rows containing 10 integrated analytical panels:

| Row | Panel # | Panel Title | Visualization Type | Query / Telemetry Basis |
|:---:|:---:|---|---|---|
| **Row 1** | **1** | Total Wazuh Alerts Ingested | Single Value | Counts all JSON records in `index=wazuh` |
| **Row 1** | **2** | High & Critical Alerts (L >= 10) | Single Value (Color Block) | Threshold filter on `rule.level >= 10` |
| **Row 1** | **—** | Distinct Detection Rules Fired | Single Value | Distinct count of active `rule.id` values |
| **Row 1** | **5** | Active Monitored Agents | Single Value | Distinct count of reporting `agent.id` values |
| **Row 2** | **2** | Alerts by Severity Tier | Donut / Pie Chart | Dynamic classification: Critical (12–15), High (8–11), Medium (5–7), Low (0–4) |
| **Row 2** | **3** | Alert Velocity Over Time | Stacked Area Chart | 1-hour timechart split by severity tier |
| **Row 3** | **4** | Top Firing Wazuh Rules | Horizontal Bar Chart | Top 10 triggered rule IDs and descriptions |
| **Row 3** | **5** | Agent Fleet Telemetry Distribution | Table | Detailed agent inventory (`agent.id`, `name`, `ip`, event count, last seen) |
| **Row 4** | **6** | Authentication Activity & Failures | Stacked Column Chart | Correlates Wazuh authentication groups into FAILED vs SUCCESS |
| **Row 4** | **8** | Observed MITRE ATT&CK Techniques | Table | Multivalue expansion of `rule.mitre.id{}` and tactics |
| **Row 5** | **7** | High-Severity Alert Triage Queue | Priority Table | Filtered stream of actionable Level >= 10 incidents |
| **Row 6** | **9** | Recent Wazuh Ingested Alerts Stream | Live Event Table | Real-time stream of the latest 20 alerts |
| **Row 6** | **10** | Investigation Timeline | Cross-Index Table | Correlates `index=wazuh`, `index=windows`, and `index=sysmon` |

## 3. Deployment Instructions

### Method A: Splunk Web UI (Classic XML)
1. Open your web browser and navigate to Splunk Web at `http://127.0.0.1:18000` (or `http://192.168.100.7:8000`).
2. Log in using your laboratory credentials.
3. In the top navigation bar, select the **Search & Reporting** app.
4. In the app header menu, click **Dashboards** -> **Create New Dashboard**.
5. Configure dashboard metadata:
   - **Dashboard Title:** `P10 - Wazuh + Splunk SIEM Integration Dashboard`
   - **Dashboard ID:** `p10_wazuh_splunk_dashboard`
   - **Permissions:** Shared in App
6. When prompted for dashboard type, select **Classic Dashboards** (Simple XML).
7. Click the **Source** tab in the edit mode interface.
8. Replace the default template XML with the complete contents of [`wazuh_splunk_dashboard.xml`](wazuh_splunk_dashboard.xml).
9. Click **Save** in the top-right corner.

### Method B: Filesystem Deployment (Ubuntu Server)
To deploy the dashboard directly via the Ubuntu server CLI:

**[Ubuntu Server]**
```bash
# 1. Copy dashboard XML to the Search app local view directory
sudo cp /path/to/p10/dashboards/wazuh_splunk_dashboard.xml \
  /opt/splunk/etc/apps/search/local/data/ui/views/wazuh_splunk_dashboard.xml

# 2. Set proper ownership to service user splunk
sudo chown splunk:splunk \
  /opt/splunk/etc/apps/search/local/data/ui/views/wazuh_splunk_dashboard.xml

# 3. Reload Splunk UI web cache without restarting the daemon
curl -k -u admin:<SANITIZED_PASSWORD> \
  http://127.0.0.1:8000/en-US/debug/refresh
```

## 4. Interactive Filters & Tokens

- **`$time_tok$` (Global Time Range):** Controls the evaluation window for all queries (defaults to `-7d@d` through `now`).
- **`$agent_tok$` (Agent Selector Dropdown):** Allows the SOC analyst to isolate telemetry to a specific agent (e.g., `win11-tgt`, `wazuh-server`) or view all reporting endpoints simultaneously (`*`).
