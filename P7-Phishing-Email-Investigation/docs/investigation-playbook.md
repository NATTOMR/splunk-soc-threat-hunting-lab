## 2. Step-by-Step Investigation Workflow

### Step 1: Alert Triage & Header Inspection
- Ingest raw email message headers and gateway metadata into Splunk (`index=email sourcetype="email:security"`).
- Verify email delivery status: `delivered`, `quarantined`, or `blocked`.
- Inspect SPF, DKIM, and DMARC verification headers:
  - If `spf=fail` and `dmarc=fail`, suspect direct domain spoofing.
  - If `spf=pass` but sender domain is external freemail (e.g. `gmail.com`), suspect display name masquerading or BEC.

### Step 2: Sender & Recipient Profiling
- Cross-reference sender address with external reputation feeds and internal directory.
- Check for homoglyph / typosquatting variations (`micros0ft.com`, `paypa1.com`).
- Evaluate recipient exposure:
  - Is recipient a C-suite executive or financial manager (Whaling/BEC)?
  - Is the email delivered to multiple internal users simultaneously (Mass Phishing Blast)?

### Step 3: URL, Domain & IP Infrastructure Analysis
- Extract all embedded hyperlinks using [`05-malicious-urls.spl`](../queries/05-malicious-urls.spl).
- Defang URLs prior to ticketing (`hxxp://login-micros0ft-verify[.]com`).
- Check host addressing:
  - Flag direct IP-literal links (`http://194.26.29.112:8080/sharepoint/token`).
  - Flag URL shorteners (`bit.ly`, `tinyurl.com`) concealing malicious destinations.
  - Query VirusTotal, urlscan.io, and AbuseIPDB for reputation scoring.

### Step 4: Attachment Forensic Examination
- Inspect attached file naming conventions and extensions using [`04-malicious-attachments.spl`](../queries/04-malicious-attachments.spl):
  - Check for dual extensions (`.pdf.exe`, `.docx.vbs`).
  - Check for script droppers (`.vbs`, `.js`, `.ps1`) or macro documents (`.xlsm`, `.docm`).
  - Check for container images (`.iso`, `.vhd`) designed to bypass Windows Mark-of-the-Web (MOTW).
- Extract cryptographic SHA-256 hash and query sandbox / threat intelligence databases.

### Step 5: IOC Extraction & Cataloging
- Collate all forensic artifacts into the [IOC Table](ioc-table.md):
  - Sending IP address & autonomous system number (ASN)
  - Sending domain and return-path
  - Landing page URLs and IP redirects
  - Attachment names and SHA-256 hashes
  - Specific lure keywords and subject lines

### Step 6: Endpoint Telemetry Correlation
- Cross-reference extracted indicators against endpoint telemetry in `index=sysmon`:
  - **DNS Queries (Sysmon EventCode 22):** Did any targeted endpoint resolve the phishing domain?
  - **Network Connections (Sysmon EventCode 3):** Did any host establish outbound TCP connections to the sending or payload IP?
  - **Process Execution (Sysmon EventCode 1):** Did Outlook (`OUTLOOK.EXE`), Word (`WINWORD.EXE`), or Excel (`EXCEL.EXE`) spawn command interpreters (`cmd.exe`, `powershell.exe`, `wscript.exe`)?

### Step 7: Incident Containment & Remediation Checklist

| Phase | Containment Action | Responsible Party | Verification SPL / Command |
|---|---|---|---|
| **Gateway** | Purge delivered message across all tenant inboxes | Messaging Admin | `Search-Mailbox -DeleteContent` |
| **Perimeter** | Block malicious sender IP and phishing domain on firewall / proxy | SOC Tier 2 | Edge / Firewall deny policy |
| **Identity** | Reset user Active Directory password and revoke active SSO tokens | IAM / Identity Team | `Revoke-AzureADUserAllRefreshToken` |
| **Endpoint** | Isolate affected host if attachment execution was confirmed | Endpoint SOC | EDR Endpoint Isolation / Netsh block |
| **Notification** | Issue security advisory to impacted user base | SOC / IT Helpdesk | Internal email notification |
