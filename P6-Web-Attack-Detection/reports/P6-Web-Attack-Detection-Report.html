1. Executive Summary

During real-time threat monitoring within the Splunk SOC laboratory, security detection alerts were triggered indicating an aggressive, multi-vector web application reconnaissance and exploitation campaign targeting the Apache2 web server hosted on ubuntu-p3 (192.168.100.9). Telemetry ingested via the Splunk Universal Forwarder from /var/log/apache2/access.log surfaced a structured adversary engagement launched from the Kali Linux host (192.168.100.6):

Key Incident Findings: Telemetry captured and parsed multiple high-severity exploitation vectors: (1) SQL Injection probes attempting authentication bypass (admin'OR'1'='1) and schema extraction (UNION SELECT); (2) Cross-Site Scripting (XSS) probes injecting script tags and DOM event handlers (<script>, onerror=, onload=); (3) Directory Traversal / LFI attempts probing sensitive Unix/Windows configuration files (/etc/passwd, /etc/shadow, win.ini); (4) Offensive Tool Scanners identifying automated agents including Nikto/2.1.6, sqlmap/1.6.12#stable, gobuster/3.1.0, DirBuster-1.0-RC1, and Nmap Scripting Engine; and (5) Directory fuzzing generating high-frequency HTTP 404 status bursts. All activities were normalized with URL decoding and correlated on the operational SOC dashboard.

3. Web Attack Vectors & Exploitation Mechanics

  • SQL Injection (T1190): The adversary submitted union-based queries and boolean tautologies within HTTP GET parameters to evaluate database parsing and extract user credentials without authentication.
  • Cross-Site Scripting (T1059.007): Reflected script injections and event handlers were submitted against application parameters, attempting client-side script execution and session token access.
  • Directory Traversal & LFI (T1083 / T1005): Probes utilized directory climb sequences (../../../../ and percent-encoded variants ..%2f) targeting system accounts (/etc/passwd) and shadow password hashes (/etc/shadow).
  • Automated Tool Fingerprinting (T1595): Vulnerability assessment suites were executed directly against the web root, exposing well-known offensive user-agent strings that require perimeter automated dropping.
  • Directory Fuzzing & 404 Status Surge: High-velocity endpoint discovery probing common administrative paths (/admin, /login, /config, /test) generated measurable 404 error spikes.

4. Search-Time Telemetry Engineering & URL Decoding

Modern web application attacks frequently leverage percent-encoding (e.g., %27%20OR%201=1 or ..%2f..%2f) to obfuscate malicious strings. The Splunk detection pipeline applies search-time URL normalization using coalesce(urldecode(uri), uri) to ensure both encoded and cleartext payloads are detected:

index=web sourcetype=access_combined | eval clean_uri=coalesce(urldecode(uri), uri) | eval attack_type=case( match(clean_uri, "(?i)(union\s+select|select\s+.*\s+from|'\s*or\s*'1'='1|information_schema|order\s+by\s+\d+|sleep\(\d+\)|benchmark\(|waitfor\s+delay|drop\s+table)"), "SQL Injection (T1190)", match(clean_uri, "(?i)(<script|%3Cscript|javascript:|onerror|onload|alert|document\.cookie|eval\(|<img|<svg)"), "Cross-Site Scripting (T1059.007)", match(clean_uri, "(?i)(\.\./|\.\.\\|\.\.%2f|\.\.%5c|/etc/passwd|/etc/shadow|boot\.ini|win\.ini)"), "Directory Traversal / LFI (T1083)", match(useragent, "(?i)(nikto|sqlmap|gobuster|dirbuster|nmap|masscan|wpscan|hydra)"), "Vulnerability Scanner (T1595)", status >= 400, "Client Error (HTTP " . status . ")", true(), "Benign Request" ) | search attack_type!="Benign Request" | eval formatted_time=strftime(_time, "%Y-%m-%d %H:%M:%S") | table formatted_time clientip method uri status useragent attack_type

8. Analyst Recommendations & Defense-in-Depth Remediation

  1. Deploy Web Application Firewall (ModSecurity with OWASP CRS):

    Install and enforce ModSecurity on Apache2 to inspect incoming URI parameters and request bodies, blocking SQLi, XSS, and traversal before reaching web applications:

    sudo apt install -y libapache2-mod-security2 sudo cp /etc/modsecurity/modsecurity.conf-recommended /etc/modsecurity/modsecurity.conf sudo sed -i 's/SecRuleEngine DetectionOnly/SecRuleEngine On/' /etc/modsecurity/modsecurity.conf sudo systemctl restart apache2
  2. Mandate Parameterized Prepared Statements: Disallow direct SQL string concatenation in backend application code. Enforce parameterized queries across all database drivers.
  3. Input Whitelisting & Output Encoding: Enforce strict contextual output encoding (HTML, JavaScript, CSS) to neutralize XSS attacks, and implement Content Security Policy (CSP) headers.
  4. Perimeter Dropping of Offensive Scanner User-Agents: Configure Apache reverse-proxy rules or Cloudflare edge rules to automatically drop requests originating from known automated vulnerability scanners (Nikto, sqlmap, gobuster, DirBuster).
  5. Automate Splunk Alerting: Schedule sqli-detection.spl and xss-detection.spl to run every 5 minutes in Splunk Enterprise, automatically alerting the SOC on Slack/PagerDuty upon pattern match.
