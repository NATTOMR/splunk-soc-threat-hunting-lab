1. Executive Summary

During operational threat hunting in the Splunk SOC laboratory, security alerts were generated indicating systematic network reconnaissance, high-volume connection velocity, and communication across unauthorized non-standard ports targeting the Windows 11 workstation (192.168.100.8). Telemetry collected via the Splunk Universal Forwarder from Microsoft Sysmon Event ID 3 (NetworkConnect) surfaced a three-phase adversary simulation:

Key Incident Findings: A total of 116 network connection events were ingested and analyzed. Telemetry captured: (1) Vertical port reconnaissance from adversary host 192.168.100.6 probing listening endpoints on TCP 22 (OpenSSH) and TCP 3389 (RDP); (2) 26 suspicious connection events directed to non-standard high port 8000 initiated by powershell.exe; and (3) an aggressive connection velocity spike reaching ~50 connections per 5-minute interval. All activities were correlated and flagged in real time.

4. Telemetry Extraction & Search-Time XML Engineering

The Universal Forwarder on Windows 11 was configured with renderXml = true, transmitting Sysmon telemetry as structured XML. Because standard field extractions do not parse XML attributes by default, regular expression extraction rules were calibrated for the Windows Event XML schema:

index=sysmon earliest=-24h | rex field=_raw "<EventID>(?<EventID>\d+)</EventID>" | search EventID=3 | rex field=_raw "<Data Name=['\"]SourceIp['\"]>(?<src_ip>[^<]+)</Data>" | rex field=_raw "<Data Name=['\"]DestinationIp['\"]>(?<dest_ip>[^<]+)</Data>" | rex field=_raw "<Data Name=['\"]DestinationPort['\"]>(?<dest_port>\d+)</Data>" | rex field=_raw "<Data Name=['\"]Image['\"]>(?<process_image>[^<]+)</Data>" | table _time, src_ip, dest_ip, dest_port, process_image | sort - _time

8. Analyst Recommendations & Remediation Playbook

  1. Inbound Firewall Hardening: Configure Windows Defender Firewall to restrict inbound SSH (22) and RDP (3389) strictly to the trusted management IP (192.168.100.1), dropping unauthorized internal subnet probes:
    Set-NetFirewallRule -Name "OpenSSH-Server-In-TCP" -RemoteAddress 192.168.100.1 Set-NetFirewallRule -DisplayGroup "Remote Desktop" -RemoteAddress 192.168.100.1
  2. Restricting Scripted Socket Connections: Deploy AppLocker policies and enforce PowerShell Constrained Language Mode (CLM) to prevent unauthorized user-mode binaries from opening arbitrary outbound TCP sockets.
  3. Scheduled Splunk Real-Time Alert: Operationalize port-scan-detection.spl as an alert scheduled every 5 minutes with a webhook to the SOC ticketing system whenever scanned_ports >= 2.
  4. Attacker Quarantine: Add dynamic firewall drop rules at the hypervisor or switch layer to isolate 192.168.100.6 immediately upon alert generation.
